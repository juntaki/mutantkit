## Highlights

- **Interrupting a run no longer loses it.** `SIGINT`, `SIGTERM` and `SIGHUP`
  stop `mutantkit run` gracefully (isolated strategy): the first signal starts no
  new mutant and lets running ones finish, the second cancels in-flight work, the
  third exits at once, and finished mutants stay in the checkpoint. `run` writes
  a partial report (an `interruption` object in `report.json`, no score), prints
  the exact command to resume, and exits `7`. Progress shows a
  killed/survived/unviable/unstable/not-materialized breakdown.
- **See which tests kill, and which look suspect.** `trust --json` gains
  `killEvidence.killingTests` (the top 10 tests by killed mutants) and
  `suspectTests` (tests that fail for at least 10 mutants across at least 5
  files). `trust` and `verify-run` report `tierAComplete` and
  `fullEvidenceReverified` separately, and `verify-run --json` carries the
  report's `executionStrategy`. These are diagnostic only: no verdict, score or
  check changes.
- **Schemata on more projects.** A compilation unit now maps to every built image
  that contains it, so SwiftPM packages with several test targets on Xcode 27 no
  longer fall back to isolated (v1.2.0: `buildReceiptUnavailable`).
  `xcodeWorkspace` is supported too, and executable and dynamic-library products
  that link a unit count as images.
- **Schemata timeout and crash verdicts can be re-verified.** They are recorded
  and, with `evidence.archive: true`, archived, so `verify-run` and `trust`
  re-check them.
- **Fewer kills lost.** A test process killed by a signal is confirmed as a crash
  kill instead of `infrastructureFailure`. With `retestKilledMutants`, the control
  runs against the live baseline sandbox, so real kills are no longer demoted to
  `flaky`.
- **`notMaterialized`.** A mutant whose build product is identical to the
  baseline's gets its own outcome. The product comparison now includes
  string-literal data.
- **Xcode 27 and build classification.** ANSI-coloured diagnostics and errors
  inside macro expansions are classified. A compiler crash is `unviable` only when
  an independent rebuild crashes the same way (same signal and compiler frames).
  SwiftPM macro targets stay isolated, and `.docc` catalogs are never mutation
  sources.
- **Operator profiles and qualification runs.** `operators.profile` accepts
  `default`, `stronger` and `all`; the v1.x values are still accepted.
  `run --require-schemata` fails (exit `6`) when schemata was not really used,
  `doctor` checks the schemata runtime (`--require-schemata-runtime` makes a bad
  one a failure), and `run` prints why each mutation fell back to isolated.

## Upgrade impact

No migration is required.

- Caches and checkpoints from v1.2.x are not reused (verifier version 16 -> 18):
  old results are misses and mutants are re-run once. A v1.2.x `report.json` still
  loads, but `trust` treats it as produced by an older verifier and exits `5`;
  re-run for a verifiable report.
- `report.json` is now schema version 2 (see below). v1.3 reads versions 1 and 2.
- Minimum requirements are unchanged.

## Compatibility changes

- `report.json` schema version 2. It can carry the new outcome `notMaterialized`
  (in v1.2.x these mutants were `infrastructureFailure`; it is not scored, is
  counted in `MutationScore.excluded`, and maps to `Ignored` in the Stryker
  report) and, for an interrupted run, an `interruption` object. v1.3 reads
  version 1 and 2 reports; v1.2 cannot read a version 2 report.
- `operator-catalog --json`: `operatorCatalogEntry` is schema version 2.
  `reachableProfile` is now `default`, `stronger` or `all`, never `conservative`
  or `experimental`.
- Exit codes: `6` (`qualificationFailed`), only with `run --require-schemata`; and
  `7` (`interrupted`). A run stopped by `SIGINT`, `SIGTERM` or `SIGHUP` now writes
  its partial report and exits `7` instead of dying from the signal. The partial
  report has no score and fails integrity, so `gate`, `trust` and `verify-run`
  refuse it, and it is not recorded to `.mutantkit/history`. The schemata
  strategy keeps the default signal behavior.
- `trust --json` and `verify-run --json` gain optional keys (`killingTests`,
  `suspectTests`, `tierAComplete`, `fullEvidenceReverified`, `executionStrategy`);
  older output omits them.
- Scores can change: signal-killed SwiftPM mutants that were
  `infrastructureFailure` can now be kills, and kills the control used to demote
  can now stand.

## Breaking changes

A v1.2 `mutantkit` cannot read what v1.3 writes in two places: a `report.json`
(schema version 2) and `operator-catalog --json` entries (schema version 2, with
different `reachableProfile` values). Mixed-version CI, such as a v1.2 `gate`
reading a v1.3 report, must upgrade together. v1.3 reads everything v1.2 wrote.
Nothing else changes incompatibly: no flag, configuration key or JSON key is
removed.

## Known issues

- Schemata does not run UI-test targets; they run isolated.
- Some sites cannot be embedded and run isolated (for example in macro targets);
  `run` and the report say why. `logical-connector-replacement` has few embeddable
  sites in some projects.
- Graceful interruption applies to the isolated strategy only.
- `retestKilledMutants` with `tests.parallel: false` leaves retest-confirmed kills
  `flaky`; enable `tests.parallel` with it.
- `verify-run` reports PARTIAL (exit `0`) when the recorded evidence archive is
  missing; keep it next to the project or pass `--evidence`.
