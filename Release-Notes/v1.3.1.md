## Highlights

- **Coverage-based test selection is much faster to set up on large suites.** The
  one-time baseline pass behind `execution.selectCoveringTests` ran one test
  process per test. The new `execution.coverageGranularity: suite` (default
  `test`, unchanged) measures each top-level suite once and credits its coverage
  to every test in it, so a mutant may run a few more tests but never fewer. On
  MutantKit's own 3,216 tests the pass took about 17-23 minutes instead of an
  estimated 2.5 hours. SwiftPM only.
- **Coverage is no longer lost for SwiftPM packages with several test targets.** On
  Xcode 27 each test target is its own bundle, and SwiftPM exports coverage
  against one of them, so code only the other target's tests execute came out as
  not executed. `selectCoveringTests` and `noCoverage` now see every target.
- **Skipped tests no longer break test selection.** A test that only ever runs as
  skipped is now attributed as covering nothing. Before, such tests entered every
  mutant's selection, could never run, and turned mutants into
  `infrastructureFailure`.
- **Schemata handles composed operands.** The logical-connector, relational and
  ternary lowerers accept composed boolean and comparison operands, so fewer
  mutations fall back to isolated execution.
- **The `stronger` profile now includes `nil-coalescing-fallback`.** The default
  profile is unchanged (six operators).

## Reports and diagnostics

- Without coverage measurement, survivors are no longer headed "Covered but
  survived". The console and HTML reports say "Survived, coverage not measured"
  and point at `execution.selectCoveringTests`; the docs now state that without it
  nothing is classified `noCoverage`.
- A build that fails with a bare `error: ...` line and no compiler diagnostic now
  quotes that line instead of "produced no compiler diagnostic".
- Acceptance failures about schemata degradation now include the run's console
  output.

## Fixes

- Hashing a universal (fat) Mach-O binary read the symbol, indirect symbol and
  string table offsets of every slice but the first as file offsets instead of
  slice-relative ones, so such a slice could not be hashed.

## Known issue

- With `selectCoveringTests`, a mutant killed only by a parameterized Swift
  Testing test can be reported as `infrastructureFailure` ("failure outside the
  selection") instead of killed. It is excluded from the score rather than
  counted, so scores are understated, never overstated.
