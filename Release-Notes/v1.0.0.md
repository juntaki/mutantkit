## Highlights

The v1.0 line closes out the trust/distribution work started at v0.4 and
locks in the contracts this tool has been building toward:

- **Stable contracts.** Exit codes, `--json` output shapes, and the
  configuration schema (`Schema/mutantkit-v1.json`, still pinned at
  `v0.3.0` — its content has not changed shape since) are now documented
  commitments, not incidental behavior. `docs/operators.md` adds a v1.x
  stability contract for the six `defaultEnabled` operators'
  IDs (`bool-literal-inversion`, `logical-connector-replacement`,
  `relational-operator-replacement`, `unary-not-removal`,
  `return-value-replacement`, `ternary-branch-swap`): none of them will be
  renamed or removed within `v1.x`, and `mutantkit gate --baseline` warns
  if a baseline ever references an operator ID unknown to the current
  build.
- **v0.9 RC closure.** Fixed four confirmed correctness gaps found during
  release-candidate audit: a configuration-precedence bug, inconsistent
  glob handling across two independent implementations (unified onto one),
  a trust-boundary gap in the merge-plan decoder, and Homebrew tap
  drift/layout issues (verified with a real, live `brew install`).
- **CI robustness, not just CI green.** The recurring `xcode-project`
  scheme-visibility flake was root-caused to a real product gap
  (`XcodeBuildAdapter.discoverSchemes` now retries a clean-but-empty
  result before giving up) and to two unrelated suites secretly sharing
  one CI job due to a substring-name collision (split, and the colliding
  suite renamed).
- **Supply-chain hardening.** Every third-party GitHub Action is now
  pinned by commit SHA; Dependabot is configured for both GitHub Actions
  and Swift package updates; the OpenSSF Scorecard Binary-Artifacts gap
  was closed by replacing a checked-in Mach-O test fixture with
  `MinimalMachO`, a hand-assembled generator with every byte reviewable in
  a diff; this project is now OpenSSF Best Practices "Passing".
  `release.yml`'s publish sequence is fail-closed: a release publishes as
  a prerelease first, and is only promoted to "latest" after the real
  published-consumer install path and the Homebrew tap sync both verify
  successfully against it.
- **Real coverage signal.** SonarCloud's Quality Gate no longer reports a
  false "0% coverage" error — the same merged `lcov.info` Codecov already
  receives is now converted to Sonar's Generic Test Coverage format and
  fed to the same analysis. Project-wide test coverage rose substantially
  across this cycle via targeted unit tests (`MuterConfigImporter`,
  `ConfigurationValidation`, `GitDiff`, the schemata lowerers' operand
  classification) and by wiring an existing, previously-orphaned
  acceptance suite into CI.
- **A coverage-guided libFuzzer target** for `MuterConfigImporter` (the
  Muter-config migration path), run on every PR and nightly on a longer
  schedule, as its own isolated SwiftPM package so it never affects the
  ordinary build graph.
- Toolchain floor raised and pinned to current Xcode (26.6) throughout CI
  and documentation (v0.8).

## Upgrade impact

No breaking configuration or CLI-flag changes for existing users pinned
to `v0.3.0`. If you pin the GitHub Action or the Homebrew formula to a
specific tag, move the pin to `v1.0.0`. The v0.9 config-precedence and
glob-unification fixes restore documented, intended behavior where a
config relied on the previous (buggy) precedence or an inconsistency
between the two glob implementations — worth a one-time review of any
config depending on subtle precedence ordering.

## Breaking changes

None.
